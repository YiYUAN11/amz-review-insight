# 交付物规格与口径

## 一、交付物清单

跑完 `run.py` 后在 `--out-dir` 生成三个文件：

| 文件 | 内容 | 用途 |
|---|---|---|
| `*_可视化.html` | 单文件网页 | 汇报、分享、嵌入看板 |
| `*_洞察分析.xlsx` | 7 个工作表 | 二次分析、筛选、导出 |
| `*_分析报告.md` | Markdown | 文档、PR、复盘 |

## 二、网页结构

| 章节 | 内容 |
|---|---|
| 一、整体摘要 | 7 个 KPI 卡 + 情感环形图 + 具象度/来源双环 |
| 二、大类分布 | 一级大类饼图 + 表1 + 表2（二级细分统计，可折叠） |
| 三、二级标签细分 | **主视图**：左侧一级→二级标签树，右侧细分模式 + 原文证据 + 全部原文墙 |
| 三、按部件维度 | 备选视图：部件 → 失效模式 → 证据 |
| 四、来源差异 | 退货 vs 评论分组柱状图 + 差异条 |
| 五、明细数据 | 全量观点明细，5 个筛选器 + 搜索 + 展开原文 |
| 六、业务解读 | 洞察卡 + 改善优先级表 |

**主题**：白天浅色（`--bg:#f4f6fa`），全部图表用原生 SVG 绘制，零外部依赖。

**中英对照**：买家原文中文为主（深色加粗），英文原文小字斜体保留在下方，可核对。

## 三、Excel 工作表

| 工作表 | 内容 | 分母 |
|---|---|---|
| 二级标签细分 | 二级标签 → 细分模式 → 现象描述 + 4 条中英原文 | 占本标签% |
| 二级标签总览 | 全部二级标签降序 | 占全部负面% |
| 部件维度×失效模式 | 部件 → 失效模式 → 证据 | 占本维度% / 占全部负面% |
| 原文证据墙 | 全部负面原文（中英对照），按二级标签归类 | — |
| 全量观点明细 | 全部观点（含中性/正向），13 列 | — |
| **交叉表_部件×模式×来源** | 部件 × 失效模式 × 来源，含「普遍 vs 个案」判定 | 占全部负面% |
| **优先级行动清单** | Top 15 综合优先级 + 建议动作 + 证据 | 占全部负面% |

### 普遍 vs 个案 判定口径

| 判定 | 条件 | 含义 |
|---|---|---|
| **普遍** | 同一模式出现在 ≥3 条**不同买家原文**，或同时出现在退货与评论两个来源 | 结构性问题，应优先立项 |
| **个案** | 只在单一来源出现，且不同原文 ≤2 条 | 偶发个例，先观察 |

**综合分** = 条数占比 × (1 + 跨来源加成 0.5 + 多原文加成)，
用于把「同一个问题跨来源出现」排到行动清单前面。

> 「未指明（原文无具体落点）」不是失效模式，**不进入行动清单**——
> 否则会把「原文没写清楚」排在真实痛点前面。

## 四、口径定义（必须遵守）

### 三种分母，不可混用

| 名称 | 分母 | 用在哪 |
|---|---|---|
| 占全部观点% | 全部独立观点数 | 一级大类表、情感/具象度分布 |
| 占本标签% / 占本维度% | 该二级标签 / 该部件维度内部条数 | 二级标签细分表、部件维度表 |
| 占全部负面% | 全部负面观点数 | 负面专项表、痛点排行 |

跨来源对比时，另加一层：**占该来源内部负面%**（退货来源内部、评论来源内部各自归一）。

> **部件识别率 / 模式命中率** 的分母是**非平台理由**的负面观点数。
> 平台下拉理由本就没有部件与模式，用它做分母会失真。

### 观点 vs 原文

- **原始文本数**：文件里的行数，一条 = 一次反馈/一条评论
- **独立观点数**：按「一条含多个独立感受必须拆」拆分后的条数

两者不等（本次实测 1377 → 2774，平均 2.0 条/原文）。

### 平台理由

`Not as Expected`、`Defective`、`Damaged`、`Changed Mind` 等是亚马逊的**固定下拉选项**，
没有具体落点。这类单独标为「平台理由」，**不参与部件归因**，在统计里独立成列。

### 具象点

判定为「有明确具象点」的条件：出现具体部件、具体现象、具体参数或时间。
`not good`、`disappointed` 这类纯情绪 → 判为「无明确具象点」。

### 归类存疑

既没命中具体部件、也没命中具体失效模式的观点，标记「归类存疑」，
在明细表里可单独筛出。**不要强行归类**。

### 叙述句过滤

描述购买背景、使用经历、他人产品对比的句子**不计入观点**：

- "I've used some other cases with a hinge cover…"（背景）
- "I came from an OtterBox Defender that ruined my screen protector"（他人产品）
- "On work-from-home days I prop the phone on my desk"（场景）

计入观点会稀释真实痛点、污染统计口径。引擎已内置过滤，但仍需 `--audit` 抽查。

### 轻微问题限定语

买家明说「不算大问题」的表述（`not a major problem` / `not a deal breaker` /
`only a minor issue`）判为**中性**，不计入硬负面。但同一句里若有其它硬负面信号
（`not a major issue but the stand wobbles`），仍判负面。

## 五、样本局限话术

每个交付物都必须包含类似表述（具体数字按实际替换）：

> 评论仅 N 条（占全部观点 X%），不足以代表整体口碑；
> 退货数据来自「已退货人群」，天然放大负面；
> 平台下拉理由 N 条（占负面 X%）无具体落点，未参与部件归因；
> 标注「未细分 / 归类存疑」的条目，是原文本身只写了 `doesn't fit`、`not working`
> 这类无落点描述，如实单列，不做推测性归类。

## 六、质量自检清单

交付前逐条确认：

- [ ] 表1 各大类条数之和 = 全部独立观点数
- [ ] 表2 各细分条数之和 = 所属大类条数
- [ ] 明细表行数 = 全部独立观点数
- [ ] 平台理由未被计入部件归因
- [ ] 交叉表里没有「未指明」进入优先级清单
- [ ] 每张图都标了分母
- [ ] 百分比两位小数
- [ ] 样本局限已写明
- [ ] 网页无外部引用（离线可开）
- [ ] 无 `NaN` / `undefined` 残留
- [ ] `validate_taxonomy.py` 无 ERROR
- [ ] `--strict` 质量门禁通过（或已知原因并说明）
