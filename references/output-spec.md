# 交付物规格与口径

## 一、交付物清单

跑完 `run.py` 后在 `--out-dir` 生成三个文件：

| 文件 | 内容 | 用途 |
|---|---|---|
| `*_可视化.html` | 单文件网页 | 汇报、分享、嵌入看板 |
| `*_洞察分析.xlsx` | 5 个工作表 | 二次分析、筛选、导出 |
| `*_分析报告.md` | Markdown | 文档、PR、复盘 |

## 二、网页结构

## 四、口径定义（必须遵守）

### 三种分母，不可混用

| 名称 | 分母 | 用在哪 |
|---|---|---|
| 占全部观点% | 全部独立观点数 | 一级大类表、情感/具象度分布 |
| 占本标签% / 占本维度% | 该二级标签 / 该部件维度内部条数 | 二级标签细分表、部件维度表 |
| 占全部负面% | 全部负面观点数 | 负面专项表、痛点排行 |

跨来源对比时，另加一层：**占该来源内部负面%**（退货来源内部、评论来源内部各自归一）。

### 观点 vs 原文

- **原始文本数**：文件里的行数，一条 = 一次反馈/一条评论
- **独立观点数**：按「一条含多个独立感受必须拆」拆分后的条数

两者不等（本次实测 1377 → 2774，平均 2.0 条/原文）。

### 平台理由

`Not as Expected`、`Defective`、`Damaged`、`Changed Mind` 等是亚马逊的**固定下拉选项**，
没有具体落点。这类单独标为「平台理由」，**不参与部件归因**，在统计里独立成列。

### 具象点

判定为「有明确具象点」的条件：出现具体部件、具体现象、具体参数或时间。
`not good`、`disappointed` 这类纯情绪 → 判为「无明确具象点」。

### 归类存疑

既没命中具体部件、也没命中具体失效模式的观点，标记「归类存疑」，
在明细表里可单独筛出。**不要强行归类**。

## 五、样本局限话术

每个交付物都必须包含类似表述（具体数字按实际替换）：

> 评论仅 N 条（占全部观点 X%），不足以代表整体口碑；
> 退货数据来自「已退货人群」，天然放大负面；
> 平台下拉理由 N 条（占负面 X%）无具体落点，未参与部件归因；
> 标注「未细分 / 归类存疑」的条目，是原文本身只写了 `doesn't fit`、`not working`
> 这类无落点描述，如实单列，不做推测性归类。

## 六、质量自检清单

交付前逐条确认：

- [ ] 表1 各大类条数之和 = 全部独立观点数
- [ ] 表2 各细分条数之和 = 所属大类条数
- [ ] 明细表行数 = 全部独立观点数
- [ ] 平台理由未被计入部件归因
- [ ] 每张图都标了分母
- [ ] 百分比两位小数
- [ ] 样本局限已写明
- [ ] 网页无外部引用（离线可开）
- [ ] 无 `NaN` / `undefined` 残留
